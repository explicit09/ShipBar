Two real defects found and fixed during verification

1. Adding the App Group entitlement deadlocked app launch. SwiftData's CloudKit mirroring hung inside CoreData's persistent-store add, so the LaunchServices-launched app never finished applicationDidFinishLaunching. Proven by bisecting the entitlement (same build launches without it, deadlocks with it) and by sampling the wedged process. Fix: pin the store URL explicitly — keeping the existing default.store filename so no existing task is orphaned — instead of letting CoreData infer it.

2. The helper was creating the App Group container. containermanagerd recorded MCMMetadataCreator = shipbarctl and never provisioned that container for the sandboxed app, whose directory reads then blocked forever in contentsOfDirectoryAtURL. This is why the bridge timed out only from /Applications. Fix: shipbarctl now refuses to create the container and reports “open the ShipBar menu app once, then try again”; the app is always its creator.

Both are locked in by regression tests. The bridge coordinator no longer swallows failures — it records why it is unavailable and what it processed, which is how both bugs were diagnosed.

Connecting the MCP server in ChatGPT Developer Mode needs the account owner's login. Setup and an authenticated tunnel script are documented in Integrations/shipbar-mcp/README.md; the capability list ChatGPT shows must be recorded there once connected.

Codex Remote invocation on a paired Mac: NOT VERIFIED.

The plugin is installed-ready and every command it issues is proven against the live app, but no run was driven from ChatGPT mobile through Codex Remote. Device pairing and host selection remain Codex Remote's responsibility.

OpenAI Platform usage (no model API call from capture): NOT VERIFIED.

Capture enrichment adds no OpenAI call by construction — no such code path exists — but the dashboard was not inspected.

Proof boundaries

  • Every ShipBar run-state change goes through AgentRunLifecycle via the signed helper; no status is reported that the helper did not acknowledge.
  • No arbitrary shell command can enter the bridge: the protocol is a closed command enum, and unknown command types fail decoding.
  • Evidence paths are validated against the run's own repository; foreign paths are refused.
  • CloudKit private storage remains the source of truth; the bridge and MCP server never touch SwiftData files directly.
  • OpenAI keys stay in the Keychain and appear in no bridge or MCP response.
